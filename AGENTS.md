# AGENTS.md — инструкции для AI-агента в проекте S4 Template HTML

HTML-шаблон на базе кодо-центричной системы **С4** (в коде и именах файлов — **S4**). Вся вёрстка — только классами С4; ручной CSS не пишется.

## Единый авторитет

Правила вёрстки С4 заданы ТОЛЬКО в JSON-контракте дистрибутива `s4/`:

- [s4/AGENTS.md](./s4/AGENTS.md) — алгоритм работы агента и внедрение S4 в проект.
- [s4/contract/patterns.json](./s4/contract/patterns.json) — точка входа: намерение UI → элемент С4.
- [s4/contract/rules.json](./s4/contract/rules.json) — запреты `R1..R6` (обязательны) и рекомендации `G1..G4`.
- [s4/contract/utilities.json](./s4/contract/utilities.json) — словарь утилит-классов (сверяй существование класса перед использованием; валидатор проверяет в любом случае).
- [s4/contract/variables.json](./s4/contract/variables.json) — публичные CSS-переменные.
- [s4/contract/elements/<папка>/<элемент>.json](./s4/contract/elements) — спецификация элемента: состав и обязательные дети, допустимый контент/запрещённые элементы (`допустимыйКонтент`/`запрещено`), модификаторы, роли (`roles`).
- [s4/contract/validate-s4.mjs](./s4/contract/validate-s4.mjs) — машинный валидатор вёрстки.

Любой `.md` вторичен: при расхождении с `contract/*.json` — истина в JSON.

## Шлюз перед вёрсткой

ПЕРЕД любой генерацией или правкой HTML:

1. Прочитай [s4/contract/patterns.json](./s4/contract/patterns.json), найди элемент под UI-намерение. Если элемента нет — семантический HTML + утилиты (`G1`); НЕ выдумывай новый `<e-*>`.
2. Прочитай спецификацию [s4/contract/elements/<папка>/<элемент>.json](./s4/contract/elements). Соблюдай состав и обязательных детей, допустимый/запрещённый контент (`допустимыйКонтент`/`запрещено`), модификаторы, роли (`roles`).
3. Сверяй существование класса в `utilities.json` перед использованием (не все сочетания `property--modifier` существуют — нет класса, бери иной модификатор/базовый). Валидатор проверяет классы в любом случае — страховка от ошибок, в т.ч. ручной вёрстки.

Не верстай карточки/сообщения/метки/иконки голыми `<div>`+утилитами и не перебивай пресеты элементов.

## Правила вёрстки

Обязательные запреты (буквально по [s4/contract/rules.json](./s4/contract/rules.json)):

- **R1** — только логические свойства: `margin-block`, `padding-inline`, `inline-size`, `inset-*` и т.п. Физические (`margin-top`, `width`, `right`) — запрещены.
- **R2** — без `!important`. Каскад решает всё без него.
- **R3** — один класс = одно свойство. Класс должен быть в `utilities.json` (базовый) или валидной Ф2-производной `property--modifier`.
- **R4** — без физических многозначных сокращений в инлайн-стиле (`margin`, `padding`, `border`, `inset` и т.п.); используй утилиты.
- **R5** — приватные переменные `--size--*` не использовать в вёрстке (ни в `class`, ни в `var()`).
- **R6** — только `:hover` как состояние; `:focus`/`:active`/`:checked`/`:disabled` классами не существуют.

Рекомендации:

- **G1** — семантический HTML сначала (`<button>`, `<table>`, `<menu>`, `<input>` вместо `<div>`).
- **G2** — Ф2 только если значение отличается от базового элемента на устройстве.
- **G3** — поверхность предпочтительно через пресет и модификаторы; прямая surface-утилита допустима по запросу дизайна.
- **G4** — допустимо навешивать `.element--{name}` на `<e-{name}>` для усиления веса селектора — это не дубль.

Прочие правила:

- **Без инлайн-стилей**, произвольных `px`/`rem` и сбросов, если не предписано контрактом. Инлайн-стиль допустим только для логических CSS-переменных (`--block-size`, `--border-radius` и т.п.).
- **Не перебивать пресеты элементов.** Нативные и кастомные элементы С4 уже стилизованы пресетом (`<button>`, `<a>`, `<input>`, `<table>`, заголовки, `<e-*>`, `<figure>` и т.п.). Утилиты — только для раскладки (flex/grid/выравнивание) и явной перебивки, запрошенной пользователем.

## Валидация

После любой правки HTML запусти валидатор и не отправляй пользователю файл с нарушениями:

- Windows: `node s4\contract\validate-s4.mjs <file.html>`
- Linux/macOS: `node s4/contract/validate-s4.mjs <file.html>`

Исправляй и повторяй, пока не увидишь `Валидация пройдена`. Подробности правил — в [s4/AGENTS.md](./s4/AGENTS.md).

## Подключение S4

S4 уже подключён в шаблоне: в `<head>` загружен `s4/js/s4.min.js` и вызван `S4()`. `s4.min.js` сам подгружает нужные CSS (`config.css`, `*-utilities.css`) по [s4/dependency-map.json](./s4/dependency-map.json) в зависимости от устройства — отдельно CSS линковать не нужно. При добавлении новых страниц подключай так же.

Файлы в `s4/` — неизменяемый дистрибутив системы: не редактируй их. Новые `<e-*>` элементы не выдумывай — состав определяется контрактом (`patterns.json`, `elements/*.json`).
